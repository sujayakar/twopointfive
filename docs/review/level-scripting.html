TL;DR. Yes, we need one. Today a set piece is a hand-rolled phase machine in src/game/ (14 t* clocks in BreachDrill), its marks half in office.json and half in module constants, its camera and its cast owned by main.ts, and its test a probe file that re-derives main.ts's call order by hand. The proposal: a Director owned by Game, ticking on the sim clock, running a level's generator-based beats against a small typed API whose actor verbs are squad.ts's (they already exist), whose stimuli hand combat.ts / destruction.ts a cause and never a result, and whose beat log is the probe and scrub substrate (the breach's beats[], generalised). Each level becomes a folder — levels/<name>/level.json (everything spatial, authored in the workbench) + levels/<name>/script.ts (that level's TypeScript, API injected, import type only) — with load-time name binding so a script naming a missing mark fails the level's lint, not the frame. The lead's folder plan stands with three amendments argued below (§0). Milestone 1 is the Director + the breach re-expressed as the office's script with probes.ts breach unchanged.

0. The lead's organisation, refined

The proposal — levels/<name>/level.json + levels/<name>/script.ts, tour and breach as the office's script with zero behaviour change as M1 — is right in shape. Evidence-based amendments:

  1. script.ts must take the API by injection and import nothing at runtime from src/. The dev server bundles the game once at start through Bun's HTML import with hmr: false (tools/serve.ts:14); a hot-swapped script that imported src/game/squad.ts would either 404 in the browser (transpile-only) or drag a second copy of Game's module graph in (bundle-on-request). So the module shape is export default defineLevel(D => { … }) with import type { DirectorApi } from '../../src/game/director' erased by Bun.Transpiler. This also makes the registration pass runnable under bun with no Game (the lint, §3).
  2. Tour AND breach in M1 is two milestones. The breach is a unit drill whose probe is order + timing windows + geometry (tools/qa/breach-probes.ts:130 ORDER / PER_MAN) — a clean first client. The tour is 13 self-contained stagings that drive the PLAYER through game.puppet (game.ts:571) with captions and a follow camera, plus goto(k) scrubbing by world reset (demo.ts:376); it exercises the showcase-only half of the API (puppet, camera, caption). M1 = Director + breach; M2 = tour.
  3. One script, several PROGRAMS. The office already has three "shows" (Demo, Breach, Attract) beside live play. script.ts exports named programs — { main, breach, tour } — exactly one active at a time; main arms on Start, the others from the card / ?breach / ?demo. The systems (QRF, needs, civilians, tactics) stay systems, generic per level once their marks are data (M5); a script may switch them (D.systems.qrf(false) for a level whose response is scripted) but does not re-implement them.

The folder also absorbs what already sprawls: levels/office.lint.json (the lint allow-list sidecar, src/editor/app.ts:8) becomes levels/office/lint.json; per-level probes and fixtures get a home (§5).

2. The Director runtime

2.1 Ownership and tick order

src/game/director.ts exports class Director; Game.director is constructed in the Game constructor after devices/destr (where qrf is) and handed the level's script module (or none: a level without a script is today's game exactly — the identity probe for M1). director.tick(dt) runs inside Game.update, immediately before tacticsTick (game.ts:1036): orders issued this frame move men this frame (the same relative order main.ts:603 gives the shows today), triggers read last frame's settled world plus this frame's g.events. Camera pin / caption / fade are outputs (director.frame: { look, pin, caption, sub, fade } | null) that main.ts reads where it reads demoPos now — one wiring for every show, forever. The clock is g.time (sim); nothing reads performance.now().

2.2 Beats are generators, run by an explicit scheduler

// src/game/director.ts — the scheduling core (signatures)
export type Cond =
  | { k: 'time'; until: number }                                   // ctx.wait(secs)
  | { k: 'pred'; test: () => boolean; label: string }              // ctx.until(pred) — polled once per tick
  | { k: 'event'; kind: GameEvent['kind'] | Signal; filter?: (e: unknown) => boolean }
  | { k: 'beat'; name: string; state: 'done' | 'started' }
  | { k: 'all' | 'any'; of: Cond[] };
export type BeatFn = (ctx: BeatCtx) => Generator<Cond, void, CondResult>;
interface LiveBeat { name: string; it: Generator<Cond, void, CondResult>; waiting: Cond | null; t0: number; step: number; state: 'running' | 'done' | 'failed' | 'cancelled'; journal: JournalEntry[] }

Each tick: (1) evaluate armed triggers → start their beats; (2) for every running beat whose waiting cond is now satisfied, it.next(result) synchronously, repeatedly, until it yields an unsatisfied cond or returns — capped at MAX_RESUMES_PER_TICK (64) per beat, a runaway logged and the beat failed; (3) collect outputs. Why generators, not async/await: a Promise continuation runs in a microtask after the current call stack — i.e. after Game.update has returned — so an awaited beat's side effects land between frames, one frame late and at the mercy of the host's task ordering; a wait() built on setTimeout runs on WALL time and is simply wrong under __runFrames / headless.ts fixed stepping (60 sim-seconds per wall-second). A generator resumes exactly where and when tick calls next(): same frame, same order, on g.time, in bun and in Chrome alike; its cursor is an integer (step) we can log, save and fast-forward to; and cancelling is it.return(). yield* composes sub-beats. The ergonomics are the same line count: yield ctx.wait(2) for await ctx.wait(2).

2.3 Checkpoints: what is saved, what re-derives

SaveState gains a director slice: { program, seed, rngPos, fired: string[] (trigger ids), signals: {name,t,data}[], flags: Record<string, Json>, beats: { name, state, t0, step, journal }[], timers, log tail } and — the enabling change — a units[] slice (spawn spec {id, team, loadout, mark, callsign} + the per-man slice savestate.ts already writes for roster men), re-spawned by id before the guard slices apply. A generator's locals cannot be serialised, so a RUNNING beat is restored by journaled replay: the beat function is re-instantiated and advanced step yields with ctx in replay mode — every verb a no-op, every cond result / ctx.rand() / ctx.query.* answer fed from the journal — so its locals rebuild deterministically, then it goes live. This is why beats read the world only through ctx.query and draw dice only through ctx.rand (the Director's own mulberry32, seeded per program run — never Math.random, like weather.ts/destruction.ts). What re-derives on load, as today: runner paths, sweeps mid-flight (restarted from the current aim), search plans. M1 cut: beats are atomic by default (a save is refused while one runs — precisely today's rule for the breach cast, savestate.ts:56); saves land between beats, where the cursor is just fired+flags+signals. Journaled replay + units[] arrive with M3, and long ambient beats opt in with { resumable: true }.

2.4 API surface

Fifteen-line summary of the surface: define-time binding by name (mark/volume/route/door/plan/loadout/lines/lightGroup) + program + expect + systems; per program, triggers (onStart/onEnter/onEvent/onStage/after/when) start named beats (generators); a beat yields wait/until/on/done/all/any, controls flow (start/cancel/signal/flag/note), reads through query/rand, commands actors (spawn/despawn/unit/side/order/arrived/release, drill.breach/clear/hold/advance/exchange, say/radio/control), the world (lights.*, doors.*, stimulus.charge/burst, objective), and — showcase programs only — puppet/press/click/camera/caption/fade/stage.

2.5 Rules the runtime enforces

  • A script never moves Sam except in a showcase: true program: puppet/press/click/stage('sam') throw otherwise, and the lint reports their static presence in a non-showcase program's beats (a syntactic scan of the transpiled module is enough — they are property names).
  • Scripted rounds are real rounds. stimulus.burst is op.weapon.fire() + fireWeapon(g, c, at, false, {steady, spread}) per round on the cadence — the breach's own statement (breach.ts:399-401) — so hits, suppression, decals, destruction heat, glass stars, hearing all follow from combat.ts. There is no kill() verb; the breach's furniture fallback (killGuard, :403) survives only as drill.breach's internal option { guaranteeDowns: true }, logged when it fires. stimulus.charge is items.spawn('flash'|…) + the fuse → detonateStun / a plume: the mains going, panes starring, dust puffs and the tile drop are destruction.ts's answer to the bang's heat, not the script's lines.
  • Error isolation. Every it.next() runs inside try/catch; a throw marks the beat failed, logs beat:<name>:threw:<message>@step, releases the units that beat spawned or last ordered (endGuardScript(u, team === 'guard' ? 'search' : 'alert') — armed men are never left frozen), clears any camera pin it held, and the frame continues. director.strict (set by headless.ts) rethrows so probes go red. A failed trigger predicate is disarmed and logged once.
  • Bounded. Units through spawnUnit's budgets (8 characters, MAX_LIGHTS; guards.ts:2893-2899) surface as a failed beat, not a dead frame; the log is a 400-row ring; ≤ 64 resumes per beat per tick; when() predicates ≤ 32 per program.
  • The beat log director.log: { t, beat, what, data? }[] gets a row for every trigger fire, beat start/yield-label/note/end, spawn, drill phase (drills forward their own beats), radio line and stimulus — the breach's beats[] for everything. It is what probes assert on, what the Director panel draws as a timeline, and what two seeded runs must produce identically.

3. Data vs code

level.json (LevelData v1 → v2, one KEYS bump, levelData.ts:217) gains: marks[] { id, floor?, pos, yaw?, notes? } (chokepoints generalised — ChokepointData is already this shape); loadouts[] { id, team, weapon, tint, tint2?, light?, trained? }; lines{} table → id → string | string[] (variants picked by ctx.rand); rooms[] { id, name, rect } (retiring chronicle.ts ROOMS); volumes[] and routes[]/plans as they are. teams stay the closed five of teams.ts until a level needs a sixth (open decision). The script references all of it by name through define-time handles: const H1 = D.mark('conf_h1') returns { kind: 'mark', id }, resolved to a Vec3 when a verb uses it. Because handles can only be made at define time (BeatCtx has no mark()), running defineLevel's callback under bun with a recording D and no Game yields the script's complete manifest — every mark/volume/route/door/plan/loadout/line-table/light-group it names, every program/beat/trigger, every expect. tools/qa/level-lint.ts and __ed.lint() diff the manifest against the document: script: mark 'conf_h3' not in level.json (used by beat 'hostiles-in') is a lint ERROR; at boot the Director refuses to arm a program with unresolved names (console error, game playable, director.armed === false) instead of throwing at minute four. Dialogue stays data the script indexes: ctx.say(u, L.qrf('moving'), { radio: true }) where L = D.lines('qrf'); the existing tables (dialogue.ts NEEDS_LINES :1628, CIV_LINES :1653) are the systems' and stay in code until M5 moves the office-specific ones.

4. Workbench "Director mode"

Serving the script. tools/serve.ts gains one route beside /qa/shader/*.wgsl (:30, the precedent for serving source off disk, no-store): GET /levels/<name>/script.js → new Bun.Transpiler({ loader: 'ts', target: 'browser' }).transformSync(await Bun.file(levels/${name}/script.ts).text()) with Content-Type: text/javascript. Type-strip only — sound because the script's only imports are import type. The game loads it with import(/levels/${name}/script.js?v=${Date.now()}) (cache-bust; old module instances are simply dropped). tools/levels-api.ts learns the folder form (GET/POST /levels/<name>/level.json, GET …/lint.json, GET …/script.js; NAME_RE per segment) and keeps answering flat <name>.json through the migration. The production bundle imports scripts statically through a generated levels/registry.ts ({ office: { data, script } }), regenerated by tools/level-export.ts, so Bun inlines them as it inlines office.json today (scene/level.ts:11).

Hot-swap semantics: re-sim, not live re-bind. Director.replace(module) re-runs defineLevel → new manifest → lint against the live document → then restart the program from t = 0 with the same seed and fast-forward to the scrub time with rendering and the smoke solver skipped (main.ts gains __simFrames(n) = game.update + lights.update, world.upload on the last frame only). Live re-binding cannot adopt new code into a suspended generator, so it degenerates to "restart the edited beat where the world happens to be" — which shows a beat in a state it will never really start from. Cost, reasoned from the harness numbers rather than measured: headless runs ~60× real time (soak: ~1 s wall per sim-minute; tour: 177 s in ≈ 3 s), i.e. ≈ 0.3 ms/frame; the field recorder puts the in-page game.update at ≈ 1.5 ms/frame (docs/perf/fieldstats-2026-08-10.json cpu.update), so the page fast-forwards at roughly 8–10×: scrubbing to t = 90 s costs ≈ 1.5 s in bun and ≈ 9–11 s in the page. Good enough for play from beat K; too slow for a draggable scrubber — so the scrubber drags over the log timeline (instant) and re-sims on release, and once units[] is in SaveState (M3) the Director drops a keyframe snapshot every 10 sim-seconds during a Director-mode run (30–90 KB each) and a scrub becomes load nearest keyframe + ≤ 10 s of re-sim ≈ 1 s. Smoke diverges across a fast-forward (GPU field not stepped); canisters' CPU side, hearing and dazzle do not — stated on the panel.

Where it lives. M3 (cheap, most of the value): the game tab opened by ▶ play from here gains Tab ▸ Director (bindings.ts rows): program picker, seed field, beat list with state dots, the log as a timeline with trigger/beat/radio/stimulus lanes, reload script (re-import + re-sim to now), play from beat K (re-sim to that beat's last logged start), pause at beat, speed ×¼…×8, and __director {log, beats, manifest, replace(), scrub(t), seed}. The workbench side gains: the marks tool (M, the chokepoint tool generalised; refs mark:<id> join RefKind), trigger volumes as they are (V), and an inspector Script tab = the manifest (programs ▸ triggers ▸ beats, each name a jump-to-entity link, unresolved names red, expects listed) fed by GET …/script.js + the define pass run in the page. M4 (the real thing): a sixth workbench mode Director that constructs a Game on the workbench's engine over loadLevel(doc.data) — the shell already runs two worlds on one engine — so edit-mark → re-sim happens in one window with the editor's camera; this needs main.ts's frame body factored into a reusable GameHost (the same refactor lets headless.ts stop re-deriving the order).

Renames. Editor.rename (editor.ts:241) rewrites references inside the document in one transact; script references are outside it. M3 rule: the editor holds the manifest, so renaming/deleting a script-referenced mark/volume/door/route pops "script.ts names this (beats: …) — rename there too" and the lint goes red until it is; no code rewriting from the browser (a textual replace through a dev-server POST is possible later but is exactly the kind of magic that bites). Undo of the rename clears the lint again — the manifest diff is recomputed on every doc.rev.

5. Testing

  • Generic script probes (tools/qa/script-probes.ts, family script, run for every level folder with a script): determinism (two seeded stand-ups, N sim-seconds per program → identical director.log digests); well-formed (every started beat ends done/cancelled; any failed = FAIL; no trigger fires twice with once); never-hits-Sam in showcase programs (tour.ts's hitFlash rule); bounded (characters ≤ 8, lights wanted ≤ MAX_LIGHTS, resumes/tick, log ring, units all despawned at program end); restore (after stop/restart: doors/switches/routes/guards = a fresh restartEncounter snapshot — breach-restore generalised); expectations — the script's own D.expect.order([...]) / within('toss','door-flung',0.2) read from the manifest, so ORDER/PER_MAN move next to the beats they describe and a re-choreography edits one file.
  • Per-level probes: levels/<name>/probes.ts exporting { [name]: (W: Headless) => Promise<boolean> }, auto-discovered by probes.ts as family level:<name> (bespoke geometry checks like the breach's funnel and L).
  • Soak: soak.ts --program main|off (default main), invariants: no unit below 'search' unless a beat holds it, no scripted man inside a static, director log ≤ cap, no beat failed, samMovedByScript === 0 outside showcase.
  • Gate: gate.sh script level:office breach before any Director merge; M1's extra gate is a frozen digest of today's breach.log (what/order, t rounded to the frame) taken on main BEFORE the port.

6. The driving example: a Seoul-style office (levels/office/script.ts, excerpt)

import type { DirectorApi } from '../../src/game/director';
export default (D: DirectorApi) => {
  const conf = D.plan('breach_conference');                 // authored in the workbench: stack, kick, toss, flows, next door
  const H = [D.mark('conf_h1'), D.mark('conf_h2'), D.mark('conf_h3')], OPS_IN = [D.mark('stair_op1'), D.mark('stair_op2')];
  const corridorBeam = D.volume('trig_corridor_laser');    // a trigger volume drawn round laser_corridor's beam
  const mgr = D.volume('trig_manager_office'), stairDoor = D.door('stairwell'), confDoor = D.door('conference');
  const hostile = D.loadout('tango_ak'), op = D.loadout('blue_fn2000'), L = D.lines('seoul');
  D.systems.qrf(false);                                     // tonight's response IS the script
  D.expect.order(['hostiles-in', 'ops-arrive', 'breach:kick', 'breach:bang', 'mains-drop', 'breach:clear']); D.expect.never('samHit');

  D.program('main', P => {
    P.onStart('hostiles-in'); P.after(75, 'ops-arrive'); P.onEnter(corridorBeam, 'ops-arrive', { who: 'sam', once: true });
    P.onEvent('bang', 'mains-drop', e => e.near(confDoor, 6)); P.onEnter(mgr, 'made-it', { who: 'sam', once: true });

    P.beat('hostiles-in', function* (c) {
      const tangos = H.map((m, i) => c.spawn(hostile, m, { callsign: `Tango ${i + 1}`, light: false }));
      c.drill.hold(tangos, H); c.doors.shut(confDoor); c.objective(L.line('obj_cross'), mgr);
      yield c.wait(4); c.control(L.pick('control_chatter', c.rand()));
    });
    P.beat('ops-arrive', function* (c) {                     // T = 75 s, or the moment Sam breaks the corridor beam — whichever first (once)
      c.control(L.line('control_go')); yield c.wait(1.6);
      const ops = OPS_IN.map((m, i) => c.spawn(op, m, { callsign: `Blue ${i + 1}` }));
      c.doors.fling(stairDoor, ops[0]); c.radio('Blue 1', L.line('blue_in'));
      const drill = c.drill.breach(conf, ops);              // stack → kick → charge → flows: the drill notes 'breach:kick' / 'breach:bang' / … itself
      yield c.any(c.done(drill.beat), c.wait(40));
      c.radio('Blue 1', drill.cleared ? L.line('blue_clear') : L.line('blue_stalled'));
      c.release(ops[0], 'search'); c.release(ops[1], 'search');   // from here they are AI: they hunt what is left, and Sam if he shows himself armed
    });
    P.beat('mains-drop', function* (c) {                     // the first charge near the conference door takes the mains — the beacons, the restrike, the dark are lighting.ts's
      yield c.wait(0.25); c.lights.mains(false); c.note('mains-drop');
      yield c.wait(22); c.lights.mains(true); c.control(L.line('control_power'));
    });
    P.beat('made-it', function* (c) { c.chronicle('objective', "reached the manager's office under the breach"); c.signal('act2'); });
  });
};

Everything after drill.breach starts is dynamic: the operatives' rounds are fireWeapon rounds that star the conference glass, pour heat into destruction.ts (paper, the TV, a ceiling tile at E ≥ 9 from the charge's bangHeat), suppress whoever they pass, and are HEARD by the shift through hearingCheck; the hostiles shoot back through the ordinary alert AI once exchange/contact hands them over; the smoke and dust are the solver's; Sam crossing the corridor is lit by whatever is still burning. The script owns when and who, never what happened.

8. Open decisions (one line each, for the maintainer)

  1. Generators vs async/await for beats — recommended generators (determinism, saveable cursor, fast-forward); the cost is function*/yield syntax in level scripts.
  2. Scrub = re-sim (recommended) vs live re-bind — re-sim shows the truth and costs ~1 s (bun) / ~10 s (page) per 90 s until keyframes land in M3; live re-bind is instant and wrong.
  3. Script sandboxing: none vs lint — recommended none at runtime (it is our TypeScript) + the define-time manifest lint + the showcase-verb scan; no eval fences.
  4. Where captions / camera / puppet are allowed — recommended: only in programs declared showcase: true; a play program can objective() and control() but never frames a shot or touches Sam.
  5. May scripts read AI internals? — recommended: only through ctx.query (escalation, unit alive/arrived/room, door/light state, Sam's room; Sam's exact position only in showcase) — never Guard fields — so the journal stays small and levels cannot grow AI shortcuts the picture does not show.
  6. Checkpoints inside a set piece — M1 refuses (as today); M3's journaled replay + units[] allows them; or rule that set pieces are always atomic and levels are written as short beats between which saves land.
  7. One script.ts with programs (recommended) vs tour.ts/breach.ts/main.ts files per level.
  8. Teams as data now or later — the closed five cover Seoul (guard/operative/hostile/player/civilian); a data table waits for the level that needs it (M6).
  9. Does the tour survive as a program at all, or does the Director's showcase half exist only for the breach-style set pieces and the tour retires when the office stops being the only level?
  10. Script edits from the browser — recommended never (IDE + hot reload); the workbench edits data, shows the manifest, and re-sims.
