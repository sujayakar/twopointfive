# WHAT A RUST START MAY DIFFER IN FROM THE TYPESCRIPT START OF THE SAME LEVEL FILE (tools/blitz/start.sh), a line a class: <path regex><TAB>why.
# Read beside known.txt. A line here is a thing the TypeScript constructor makes that no rule of the Rust tick reads (checked by a search of
# rust/game/src for the field), or a number the two sides deal differently by design. Anything a rule reads is mended in the start, not named here.
^g\.col\.mirror\.[a-z_0-9]+$	harness: where the box mirror's tables stand in each module's memory (addresses)
^g\.col\.trig_(yaw|cos|sin)(\.len|\[)	a memo: the collision's sines and cosines by box, filled as the TypeScript asks; the Rust asks the maths each time
^g\.snow_look_was$	picture: the snow look's marker (Game.syncSnowLook is the picture's and empty in Rust)
^g\.rig_fits	picture: the proxy fits of the cast's rig, solved for the renderer (render/sdfrig.ts)
^g\.mesh_shadows\.	picture: the mesh shadows' tree over the character's triangles (render/meshShadows.ts)
^g\.props\.store\.epoch$	a memo's stamp: which block the furniture's tables were made from
^g\.m\.scene_box_mirror\.held(\.len|\[)	harness: the copies of the box mirror this process holds
^g\.m\.owner\.witnesses(\.len|\[)	a check's table: the rules with a witness, filled as the TypeScript modules load (owner.ts); no rule reads it
^g\.m\.fogofwar\.thing_pass(\.len|\{)	the same set said two ways: the TypeScript adds the wall skin's system to the set, the Rust tests it beside the set (fogofwar/p_02.rs)
^g\.m\.kit\.row_cache(\.len|\{)	a memo of a pure function (kit.ts rows by switch word)
^g\.tab\.anim_gltf_mesh_data\[c\d+\]\.joints#$	bridge (inferred, not traced in export.ts): the wire names the first arm of the union Uint16Array | Uint8Array for the cast's joints; the loader makes a Uint8Array on both sides (gltf.ts loadGltfCast) and no rule reads a mesh
^g\.engine\.world\.glass_list(\.len|\[)	the picture's: the panes listed to the GPU nearest the camera's focus first, written by the world's pack (boxes.ts packGlass), which a host that draws nothing does not run; read by the debug panel's line alone (glass.ts glassSummary)
^g\.snow_(field|tracks)$	the picture's: a snow level's lying snow as one surface and the prints boots press into it (render/snowField.ts, game/snowTracks.ts), made by Game.syncSnowLook for the g-buffer; the Rust game leaves that call empty (game/p_03.rs) and no rule reads either
^g\.m\.scene_markings\.area_lit_marks(\.len|\{)	bridge: the TypeScript's set is a WeakSet of mark objects (markings.ts AREA_LIT_MARKS), which the bridge cannot list and writes as empty; the Rust's holds the marks the constructor registered as lights (game/p_04.rs), and the picture's pack alone reads it (scene_boxes/p_01.rs)
