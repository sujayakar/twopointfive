# THE KNOWN DIFFERENCES between the TypeScript game's state and the Rust game's after a tick: a line each, `<regex of paths><TAB><why it is no fault of a rule>`.
# Read by diff.ts: a differing path that matches a line is counted and left out. Add a line only with its reason, and take a line out when its cause is mended.
# Paths are diff.ts's: a row of a table numbered by reach reads [c12]. The kinds: bridge (the export walks the two sides differently) · host (the host's doings
# between ticks, not run on the Rust side) · harness (this loop's own doing) · picture (state only the renderer reads, which the Rust tick does not fill) ·
# skeleton (a type the Rust skeleton cannot yet say).
\.mirror\.(copy|epoch)$|scene_box_mirror\.copies\.n$|scene_box_mirror\.held\[\d+\]\.	harness: the module's copy of the box world is made afresh in a fresh module (its number, its marks); `held` is a second copy of the same mirror
^g\.fog_of_war\.frame\.|^g\.fog_of_war\.(lamp_pick|lamp_n|lit_stats)	picture: the fog's GPU block and its lamps' list (triage: fogofwar "lamps … only feed the renderer")
^g\.serial_next$	bridge: the serial counter itself. The walk deals a serial by identity as it meets a record, Rust from g.serial() as it makes one: the same records, other numbers (a field that holds one is left out by rule: schema.serial)
^g\.props\.stats\.ms$	the wall clock (a stat)
^g\.m\.anim_gltf\.(nvg|suit)_bits	a memo of a pure function of the cast (gltf.ts), kept where the TypeScript's walk cannot see it
^g\.fog_of_war\.fired_n(\{|\.len$)	bridge: FogOfWar.firedN is keyed by the Op OBJECT (fogofwar.ts:439); the walk deals a serial as its key, Rust keys by the op's ID
^g\.m\.doze\.left	bridge: a table keyed by the game that has no row (doze.ts LEFT) is written as an empty one; Rust's None is the TypeScript's truth
^g\.chars\.	picture: the character renderer's own marks (anim/characters.ts)
\.mirror\.(used|things_at)$|scene_box_mirror\.clock\.n$|scene_collision\.anytime\.windows$	host: the asks the headless host makes of the box world BETWEEN ticks (a window opened, a clock ticked); not run on the Rust side
^g\.orders\.view\.(input|cam)$	host: the menu's host view
^g\.(tab\.cmd_seat\[c\d+\]\.own\.)?work\.cache	harness: a memo (key, time) the test driver's `orders.targetAt` fills between ticks (orders.ts targetAt asks workthings.ts workNear, whose `things()` keeps its list for a second); the Rust runner builds the driver's target itself. ^g\.m\.doortools\.sky(\.len$|\{)	harness: a memo of a pure function of a room (doortools.ts:761 SKY, underSky), first filled BETWEEN ticks 1009 and 1010 by the test driver's own question with a room `roomAt` flooded for it (the state as the next tick opens shows the host wrote it); the Rust game fills its own when its tick asks
clip_side\{.*\}\.at$	bridge: ClipSide.at is written -2 (not yet asked) by the walk so that the Rust store is asked again on first use; Rust then holds its own slot numbers
scene_collision\.sensed\.light$	host: a count of light asks; the headless host / the test driver asks between ticks too (+2 with no tick run)
scene_collision\.rays\.n$	picture: a count of rays cast. The TypeScript's includes the decals' placement rays (marks.ts:55-70 bangScorch: one down and sixteen round, at a stun grenade's burst); marks are a boundary no-op in Rust (Game.decals is not carried)
^g\.m\.frag\.books\[\d+\]\.flee\{.*\}\.serial$	bridge: a serial dealt by the walk to a lent script no Rust body numbers, as script.serial
^g\.m\.frag\.books\[\d+\]\.rest\.t$	harness: when the flee's guess of a grenade's rest was last made. The test driver's own cue question between two ticks makes it again once the grenade has settled (frag.ts restOf, stamped with the time of the tick before); the Rust game makes it in its next tick. A settled guess is kept for good and its time is not read again; where it lies (rest.at, rest.still) is compared
^g\.m\.frag\.walls_for(\.time)?$	harness: the flee's memo of the walls a grenade's burst would open (frag.ts wallsFor, asked once a tick for a point). The test driver's own cue question fills it between two ticks, one tick before the Rust game's tick first asks (the state as the next tick opens shows the host wrote it); where both hold it, its rows are compared
^g\.m\.dialogue\.room_rects$	host: a memo of a pure function of the level (dialogue.ts roomRects: the rooms' walls). The HUD's asks between ticks fill it from the first frame; the Rust game fills its own when a tick first asks (Some / None until then). Where both hold it, its rows are compared
^g\.m\.hours\.(states|nights)\.(cells|fine)(\.len$|\{\d+\}$)	harness: the hour's kept rays of a half-metre cell, asked once (hours.ts skyLight). A lesson's scripted player asks the light on its own man between ticks to feed his meter, which keeps cells no tick asked; a cell both sides hold is compared ray by ray
^g\.tab\.cmd_seat\[c0\]\.own$	skeleton: in a game of several seats the TypeScript keeps a record of the seat's own fields for EVERY seat, the first too (seats.ts seatsStand); the Rust game keeps the first seat's on Game itself while no other seat's view is open (seats::with_seat changes them over), so its first seat's `own` is None. The fields themselves are compared: the first seat's as the Game's, a later seat's under its `own`
^g\.m\.seats\.seat_asks\.	harness: a check's count of how often the Game's own seat field was asked inside a tick of a game of two (seats.ts SEAT_ASKS.misses); the Rust game has no such accessor to count. tools/blitz/seats.ts --asks prints the TypeScript's sites and the first tick
^g\.wall_charge\.walks\.menu$|^g\.tab\.cmd_seat\[c\d+\]\.own\.wall_charge\.walks\.menu$	bridge: which menu the wall charge's kept walks are of, an identity (wallcharge.ts keptWalks `k.menu !== M`): the walk deals the menu OBJECT a serial, Rust holds the serial of the menu's own target. schema.serial does not mark it
^g\.tab\.director_live_beat\[c\d+\]\.it(\.len$|\[)	bridge: a running beat's frame as the Rust game holds it (LiveBeat.it, a counted blob kept beside the puppet's object and handed back as it came): the TypeScript's own export has none to write, a generator's place being no data there
^g\.tab\.director_live_beat\[c\d+\]\.waiting\..*\.test\.\d+$	bridge: a waiting beat's test (Cond.test) by its number in the level's script, as the Rust game holds and carries it; the TypeScript's own export writes 0 there (a test is a closure to it, and it has no number to write)
^g\.col\.mirror\.put_backs$	host: a count of checkpoints put back, kept by the TypeScript's box mirror when the host's save controller replaces the game; the Rust game is handed the state as a new start and counts none
